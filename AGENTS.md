- LinkedIn crawling is brittle: fail explicitly with context.
- Indeed crawling is Cloudflare-protected from cloud IPs: provide a trusted session via `bin/rails indeed:login` and fail explicitly on challenge pages.
- WeLoveDevs is a client-side Algolia InstantSearch app (no auth/session, no anti-bot): the whole provider runs as plain HTTP via Faraday — no Playwright, no HTML scraping. The public `public_jobs` index is open (app id + search-only key embedded in the site bundle), and a hit carries the entire offer, so discovery and fetch both call Algolia directly. Discovery `POST /1/indexes/*/queries` (`query=`, `hitsPerPage`, `page`), keeps only `type=="company_job"` hits, and builds `/app/jobs?jobId=<objectID>` URLs (objectID is URL-encoded — often contains `+`). Fetch decodes `jobId` and calls `GET /1/indexes/public_jobs/<objectID>`, storing the raw JSON; 404 → gone offer; legacy `/app/job/<seoAlias>` URLs (previous Playwright impl) carry no `jobId` and are retired as gone. Analyze is fully structural: `contractTypes[]`→employment_type (PERMANENT priority); `details.salary` yearly-only, scaled ×1000 (`€`→EUR); `details.remotePolicy.frequency` (fullTime→remote, hybrid→hybrid, no→on-site); markdown `mdDescription` rendered to HTML via kramdown. `supports_work_mode_filter?` is false. The Algolia keys are unofficial public constants — every step fails loudly on HTTP/shape drift.
- Collective.work is a public Next.js freelance marketplace (no auth, no anti-bot): both discovery and fetch are plain HTTP via Faraday — no Playwright. Discovery reads the SSR React-Query payload at `__NEXT_DATA__.props.pageProps.dehydratedState.queries[0]` (queryKey `PublicPages_SearchJobs`) and paginates via `?page=N` with keyword filter via `?search=` (verified: passes through to SSR; `workPreferences` does NOT, so `supports_work_mode_filter?` is false). Analyze reads `__NEXT_DATA__.props.pageProps.project` structurally — no JSON-LD is emitted. Contract mapping is binary (`isPermanentContract` → PERMANENT/FREELANCE); salary is parsed only for permanent contracts (freelance `budgetBrief` is a daily rate on a different scale and is left nil to preserve the annual `salary_min_minor` convention). A null/missing `project` payload is treated as a gone offer.
- Free-Work is the largest French IT board (freelance + CDI) with an undocumented but open API Platform JSON API (no auth, no key, no anti-bot): discovery and fetch are plain HTTP via Faraday — no Playwright, no HTML scraping. Discovery hits `GET /api/job_postings` (`Accept: application/ld+json`, hydra collection) with `searchKeywords=` and `remoteMode=full|partial|none` — both filter server-side, so `supports_work_mode_filter?` is true; pagination follows `hydra:view["hydra:next"]`. Fetch maps the public URL's `/job-mission/<slug>` to `GET /api/job_postings/<slug>` and stores the raw JSON; HTTP 404 → gone offer. Analyze is fully structural from that JSON; `contracts[]` maps to employment_type with PERMANENT priority; only the annual salary channel is read (freelance daily rates left nil to preserve the annual `salary_min_minor` convention). The API is unofficial — every step fails loudly on shape drift.
